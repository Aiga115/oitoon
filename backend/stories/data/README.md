# Demo story data

This folder contains `tinystories_sample.json`, a small sample of stories used **only** to fill the Oitoon demo with content (see the seed management command, Sprint 7).

## Source

- **Dataset:** TinyStories (version "V2-GPT4"), validation split, file `TinyStoriesV2-GPT4-valid.txt`
- **Dataset page:** https://huggingface.co/datasets/roneneldan/TinyStories
- **Paper:** https://arxiv.org/abs/2305.07759
- **Licence:** CDLA-Sharing-1.0 (the licence name is shown on the dataset page, which links to the full text)
- **Downloaded:** [date]

The stories in this dataset are synthetic: they were generated by GPT-3.5 and GPT-4 and use a small vocabulary.

## What was done with it

The large original file is **not** stored in this repository. A script cut a small sample out of it:

- Script: `docs/tools/make_demo_sample.py`
- The original file was split on its `<|endoftext|>` markers.
- Only stories between 400 and 1500 characters were kept.
- The first 60 of those stories were written to `tinystories_sample.json`, as a list of plain-text strings.
- The texts themselves are not edited.

Command used:

```bash
python3 docs/tools/make_demo_sample.py TinyStoriesV2-GPT4-valid.txt backend/stories/data/tinystories_sample.json 60
```

## How Oitoon uses it

The seed command reads the JSON file and creates demo stories in the database. Everything except the story text is **generated by the command**:

- titles (taken from the first sentence)
- authors (fake demo users)
- genres (assigned by simple keywords, so they are only a rough guess)
- statuses
- ratings (random, in a few "taste groups")

So the demo data is synthetic. Recommendations shown on it demonstrate how the algorithm works; they do not reflect the taste of real readers.
